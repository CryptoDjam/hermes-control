## Lot B — identities (PROTOTYPE on branch `lot-b-identites`, 2026-10-08; not merged, not published, not deployed)
C2 of Codex's coherence review (two homonymous agents sharing one business folder and memory). *Coded* and *tested* (unit tests + isolated bwrap run with a simulated Paperclip API); not run in a Paperclip server.
1. **Short term — one owner per business folder** (`src/proprietaire.ts`, `prepareAgent`): `owner` (companyId, agentId) is now required; the folder is created atomically with `.hermes-control/proprietaire.json`; an existing folder owned by another identity, or **without a recorded owner**, is refused before anything is created (no automatic adoption: migration inventory). Foreign links refused (folder, sub-folders, profile `memories`, `journal`, profile reached through a link) and never followed or replaced.
2. **Target — reads the pack's projection** (`src/identites.ts`, `src/prepare-identite.ts`, `readAssignments`): with `<ws>/donnees/identites.json`, profiles are `donnees/h/<i>/profiles/<a>` and data `donnees/e/<e>/a/<a>`; refusals: invalid projection, missing alias, company mismatch, retired/unassigned agent, competing `assignments.json` (companies/agents), assignment writes from HC.
4. **Inactive identities refused, stale projection refused** (branch `lot-b-statuts`, after Codex's final review of 2026-10-08): statuses are a **closed list** (`actif`, `absent`, `retire`) for companies and agents, anything else makes the projection invalid. An agent runs (prepare, execute, resume, adapter skills) **only if its company AND the agent are `actif`**: `absent` is preserved (alias, folders, memory, assignment kept and still shown) but cannot run; `retire` never runs again. The refusal is a configuration refusal (`hermes_control_inactive`, `configuration_incomplete`: not retried). **Stale projection** (`src/identites-fraicheur.ts`): HC keeps, in its own reference folder, the highest revision read per envelope with its sha256 and counters; a lower revision, the same revision with different content, or an alias counter going back is refused (re-read once before refusing).
5. **Freshness hardened, controlled restoration, versioned refusal contract** (branch `lot-b-fraicheur`, after Codex's review of 2026-10-08 §0–§1 and the GO of the four work items): the freshness state is never treated as empty — a truncated, unreadable, permission-denied, schema-invalid or legacy state, a state deleted after use (detected through an independent envelope marker `donnees/.hermes-control-suivi.json`) or a restoration in progress is refused (`etat_suivi_invalide`); a never-initialized envelope is refused (`suivi_non_amorce`) until the operator bootstraps it explicitly. Counters are kept at the highest known value, retired identities are tombstoned (a retired identity put back active, or dropped, under a higher revision is refused), aliases never change identity. Atomic writes (exclusive tmp + fsync + rename + directory fsync) under lock, `.prec` and a second copy of the maximum in the marker. New operator command `hermes-control-suivi` (`etat`, `amorcer`, `restaurer`, `notifications`): operator only, one envelope, refuses while a writer runs, raw backup with sha256, before/after report, reliable maximum from every known source, resumable, `restauration` event in a bounded local queue (loss visible and replayable). Refusals carry a versioned `identite_inactive` object (schema 1, structured cause) in `resultJson`, Paperclip's fields unchanged; bounded `refus.jsonl` that never blocks a refusal. Contract with the pack: `docs/restauration-identites.md`.
3. **T16 before creation**: `prepareAgent`/`prepareByIdentity` measure the literal `HERMES_HOME` (administered execution root included) before the lock, the profile clone or any folder; `bot-desktop/rfb.sock` added to the expected sockets (launch check and diagnostics).
