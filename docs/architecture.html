Hermes Control — Hermes moteur, Paperclip aux commandes

Plugin Paperclip signé Cyril M · version 0.3.0, état au 3 octobre 2026 (soir) · code : ~/.claude/projects/hermes-control/

1. Le principe

Paperclip est le maître. Pour chaque agent, Paperclip envoie cinq données : son nom, son working directory, son provider, son modèle, son thinking. Avec le nom, Hermes Control trouve le profil Hermes correspondant ; provider / modèle / thinking y sont écrits et Hermes tourne dessus. Dans l'autre sens, les menus Provider et Model du formulaire de base de l'agent listent ce que Hermes connaît. Rien d'autre n'entre ni ne sort. Deux pièces dans un même projet : un adaptateur (remplace l'adaptateur Hermes intégré) et un plugin (synchro + une vue « instances »).

Règle d'or : une seule source de vérité, Paperclip. Hermes Control ne crée pas de page de réglages : il remplit les menus existants et recopie les choix dans Hermes. Les clés ne sont jamais lues ni affichées ; aucune commande ne passe par un shell.
Pourquoi un adaptateur : les menus Provider / Model du formulaire de base appartiennent à l'adaptateur Hermes de Paperclip, pas aux plugins. Paperclip permet officiellement de remplacer un adaptateur intégré par un adaptateur externe (pause / retour arrière à tout moment : paperclipai adapter override hermes_local).

La synchronisation Paperclip → Hermes

Déclenchée à chaque modification d'un agent (agent.updated / agent.created), à l'ouverture de la vue, et toutes les 5 minutes. Le plugin compare config.yaml du profil aux valeurs Paperclip et n'écrit que les différences : model.provider, model.default, reasoning_effort (thinking, seulement s'il n'est pas « auto »). Valeurs validées (lettres, chiffres, .-_:/), exécution hermes config set sans shell.

3. Comment le nom choisit le Hermes

  1. Le nom de l'agent est mis en minuscules sans accents : « Apolline M » → apolline-m, « Chef » → chef.
  2. On cherche un profil Hermes du même nom (profiles/apolline-m, profiles/assistant).
  3. Sinon, un profil dont la description commence par ce mot : « Chef — PDG… » → profil default de l'instance direction ; « CMO — … » ; « Chercheur — … ».
  4. Trouvé → le passage tourne avec HERMES_HOME de ce profil (plus besoin de lanceurs par agent) ; pas trouvé → le passage s'arrête avec la liste des profils connus.
  5. Les instances sont cherchées dans ~/.hermes et dans les dossiers listés dans ~/.config/hermes-control/roots (pour CDjam : ~/Projects/ProjetC/hermes/profils).
Thinking : Paperclip range le « Thinking effort » d'un agent Hermes dans ses arguments (--reasoning-effort) ; le plugin le recopie dans le profil Hermes quand il n'est pas « auto ».

4. Sécurité

  • Commandes hermes lancées sans shell (arguments séparés), noms de profils validés ([a-z0-9._-]).
  • state.db ouverte en lecture seule avec node:sqlite (rien à compiler).
  • Aucune clé lue, aucun réseau sortant (capacité http.outbound non demandée).
  • La seule écriture (modèle d'un agent) passe par l'API Paperclip avec la session de l'utilisateur, jamais par le worker.

Leçons apprises en construisant

  • Le manifeste du serveur exige jobKey (pas key) ; le valider avec le schéma zod de @paperclipai/shared avant d'installer.
  • Le worker doit finir par runWorker(plugin, import.meta.url), sinon le processus sort aussitôt (code 0) et Paperclip marque le plugin en erreur.
  • Une dépendance CommonJS (yaml) dans un bundle ESM a besoin d'un createRequire en bannière esbuild.
  • paperclipai plugin init plante (paquets manquants) : squelette écrit à la main.
  • Les jobs planifiés tournent sans périmètre entreprise : config.get / agents.list y sont refusés → le job relit les instances mémorisées dans l'état du plugin.
  • Paperclip lance le worker sans HOME : utiliser os.homedir().
  • Pas d'emplacement de plugin sur les agents dans cette version ; les menus de l'agent appartiennent à l'adaptateur → d'où l'adaptateur Hermes Control qui remplace l'intégré.
  • Un adaptateur externe s'installe par chemin local (adapter install --payload-json '{"packageName":"…","isLocalPath":true}') et doit exporter createServerAdapter().
